# Astryx components

## Groups
- Chat: Conversational messaging primitives for building chat UIs, AI assistants, and threaded conversations. Main component: ChatComposer.
- Checkbox: Selection controls for choosing one or more options from a set. Main component: CheckboxList.
- Layout: Structural primitives for arranging and spacing content on a page. Main component: Stack.
- Radio: Selection controls for choosing exactly one option from a set. Main component: RadioList.
- Tabs: Tabbed navigation for switching between content views without a page reload. Main component: TabList.
- Utilities: Providers and configuration components for theming, routing, and rendering context. Main component: Theme.

## Components
Each has a page in components/<Name>.md.

- Button (Action): action trigger w/ 4 variants, 3 sizes, loading state
- ButtonGroup (Action): connected button group w/ shared borders, outer-only radius, horizontal/vertical
- DropdownMenu (Action): dropdown menu for actionable items in popup
- IconButton (Action): Button showing only an icon, no visible text. Use in toolbars, table rows, compact UI where space is tight + icon universally understood.
- Link (Action): Styled anchor links w/ multiple variants + polymorphic link infra for custom link components (Next.js Link, React Router Link, etc.).
- MoreMenu (Action): Overflow menu w/ three-dot icon trigger. Convenience wrapper composing icon-only Button w/ dropdown menu, eliminating boilerplate for state management, positioning, accessibility.
- SegmentedControl (Action): A segmented button group that allows users to make a single selection from a small set of mutually exclusive options. Use SegmentedControl when all options should be visible at once and the selection controls a value or mode, not page navigation. Under a finger, on a touch device (a coarse primary pointer), the selection slides to the new segment, whether a tap, an arrow key or a new value moved it; with Reduce Motion nothing travels: the old selection fades out as the new one fades in. There, pressing the selected segment lifts it, and dragging it carries the selection along with the selected label’s colour following it, and the segment under the finger is chosen when it lets go; a tap selects through the browser’s click; a pressed unselected segment shows the shared pressed overlay, and nothing dims. A drag that drifts off the control still chooses by its position along it. Going back to the selected segment, or Escape, changes nothing. With a mouse or a pen every change, a click included, slides on the theme’s duration and easing, and dragging the selected segment carries it as a finger does.
- ToggleButton (Action): toggle btn w/ pressed/unpressed states, icon swap, group integration for single/multi-select
- Toolbar (Action): Horizontal bar w/ left, center, right areas. For contextual actions in content, not page headers. Size cascades to children.
- Chat (Chat): AI chat components. Layout (MessageList>Message>Bubble+SystemMessage) + Composer (shell w/ slots, ContentEditable input w/ trigger menus, tokens, msg history, attachments)
- ChatToolCalls (Chat): tool/function call display from LLM response; single=inline, multiple=collapsible summary w/ latest at surface
- Card (Container): bordered container for DISCRETE items; NOT the default layout tool. Most content doesn't need a card.
- Carousel (Container): horizontal scroll container w/ fade edges, nav buttons, scroll-snap
- ClickableCard (Container): Interactive card for navigation/action targets. Nested interactive elements work independently.
- Collapsible (Container): hide/reveal content behind a trigger; group for accordion behavior
- SelectableCard (Container): Card toggling between selected/unselected states w/ accent border. For navigation use ClickableCard instead.
- Avatar (Content): person/team avatar w/ photo → initials → icon fallback chain
- AvatarGroup (Content): compositional overlapping avatar row w/ +N overflow or custom slot
- Blockquote (Content): quotation block w/ inline-start rule, secondary text, optional citation
- Citation (Content): Inline reference to external source. Attribute info in AI responses, articles, or anywhere provenance needed.
- Code (Content): inline semantic code for short technical references in prose; CodeBlock handles standalone or multi-line snippets
- CodeBlock (Content): syntax-highlighted code block via CSS Custom Highlight API (0-DOM overhead); span-based fallback; Code for inline code in prose
- EmptyState (Content): placeholder when a content area has no data: icon, title, description, action buttons
- Icon (Content): Renders icons w/ Astryx design system colors + sizes. Supports direct SVG icon components + semantic icon names that adapt to active theme.
- Kbd (Content): Renders keyboard shortcut as styled key badges. Use in tooltips, menus + help text to show key combinations.
- Markdown (Content): Renders markdown string as Astryx-styled components. Use for user-generated content, AI responses, docs. Headings, lists, tables, code, citations w/ consistent styling.
- Text (Content): semantic body text + headings w/ theme-driven type scale, truncation, tabular numbers
- Thumbnail (Content): Square preview card for image attachments. Skeleton shimmer on upload, image on success, placeholder when no src.
- Timer (Content): Standardized elapsed or stopwatch duration with clock-derived, non-rendering DOM updates.
- Timestamp (Content): formatted timestamp with relative/absolute/auto modes, live updates, timezone display, and a copyable multi-zone hover card (default single full-time row, customized via tooltipEntries)
- Token (Content): compact chip/tag for inline metadata, filters, selections. 11 colors, 3 sizes, removable, clickable, linkable.
- Badge (Feedback & Status): highlights a status or category tag, NOT for general metadata
- Banner (Feedback & Status): persistent message for errors, updates, warnings, or confirmations
- InfoTip (Feedback & Status): Inline info-icon help affordance: accessible "i" button trigger pre-wired into a Tooltip.
- ProgressBar (Feedback & Status): Progress bar for displaying determinate or indeterminate progress.
- Skeleton (Feedback & Status): An animated shimmer placeholder that previews the shape of content while it loads. Use it to build loading screens that match the layout of the real content. For content with unknown dimensions, use Spinner instead.
- Spinner (Feedback & Status): An animated loading indicator for processes with unknown duration, such as data fetching or form submission. Supports visible labels, multiple sizes, and a dark background variant. For content with known dimensions, use Skeleton instead.
- StatusDot (Feedback & Status): Small colored dot indicator for status display (online/offline, severity, etc).
- Calendar (Form Controls): month grid for picking a date or date range
- CheckboxInput (Form Controls): single on/off toggle for settings, terms, and opt-in choices
- ComplexSelector (Form Controls): Input/secondary/ghost trigger + dialog-popover shell for rich custom selectors. Content gets value/onChange/close/state; content owns semantics. Use focus hooks and evaluate custom content against WCAG 2.2.
- DateInput (Form Controls): text input w/ calendar popover for picking a date
- DateRangeInput (Form Controls): date range picker with dual-month calendar popover and preset ranges
- DateTimeInput (Form Controls): combined date + time picker with calendar popover and time input
- Field (Form Controls): Low-level field shell for custom controls needing label/description/status.
- FileInput (Form Controls): File input w/ input/dropzone modes, validation, label, description, status.
- MultiSelector (Form Controls): checkbox multi-select dropdown for finite sets like column toggles or filter facets
- NumberInput (Form Controls): Number input component for collecting numeric user input w/ validation.
- PowerSearch (Form Controls): Structured filter bar where each token represents filter (field+operator+value). Users select fields from typeahead dropdown, configure operators+values in edit popover, manage filters as removable tokens.
- RadioList (Form Controls): Radio group component for single-value selection from list of options.
- Selector (Form Controls): A dropdown selector for choosing a single value from a list of options. Supports labels, validation, descriptions, and required/optional states. Use it in forms and settings when presenting a moderate number of options. Keyboard typeahead matches a native select: typing on the focused closed trigger selects the matching option directly, repeated presses cycle through options sharing a first letter, and spaces count as match characters ("new y" reaches "New York"). With the menu open, typing moves the highlight and Enter commits. With hasSearch, typing on the closed trigger opens the popup and seeds the search input.
- Slider (Form Controls): A draggable control for selecting a numeric value or range within defined bounds. Supports single value and range selection, tick marks, custom value formatting, and vertical orientation. Use it when users need to explore a continuous range, such as volume, price, or percentage. Under a finger, on any touch device, it tracks as UISlider does: only the thumb takes a drag, through a target larger than it, the value follows the finger’s travel rather than jumping to it, a release coasts on before `onChangeEnd`, a swipe from the track scrolls the page, and a tap on the track or a mark sets the value when the finger lifts (the thumb springs there). A mouse drag on a thumb tracks the same way, past the same 10 px in any direction, with no lift or coast; a mouse press on the track moves the thumb there, and only a primary click presses. A pen drags as a finger does, claiming only along the track, and its drag ends at the release with no coast. A wheel or a trackpad scroll over the slider goes to whatever scrolls under it.
- Switch (Form Controls): Toggle switch for boolean values w/ integrated label support.
- TextArea (Form Controls): Multi-line text input for collecting longer user input.
- TextInput (Form Controls): Text input for collecting user text w/ label, description, validation status, optional/required indicators.
- TimeInput (Form Controls): Time input with browser/OS picker on touch by default and Astryx typed-field fallbacks for seconds or custom increments.
- Tokenizer (Form Controls): Multi-select typeahead w/ token chips for selected items. Composes BaseTypeahead for search+Token for chips.
- Typeahead (Form Controls): Searchable dropdown for single-item selection w/ keyboard navigation. Supports async+sync search via searchSource interface.
- AppShell (Layout): app-level layout shell w/ header, side nav, main content; composes Layout internally, replaces Page+PageLayout
- AspectRatio (Layout): maintains specific aspect ratio for children
- Divider (Layout): visual separator w/ optional label, using Astryx design tokens
- FormLayout (Layout): Layout container for form fields w/ consistent spacing + direction.
- Grid (Layout): CSS Grid-based layout w/ responsive column support.
- Layout (Layout): General five-slot primitive for arranging header, start, content, end, and footer regions. AppShell owns the page shell.
- Resizable (Layout): Hook-based resizable panel system. useResizable() manages size state; ResizeHandle provides interactive pill-grip separator.
- ScrollableArea (Layout): native logical-axis scroll viewport with conditional keyboard access, live edge state, and observed content geometry
- Section (Layout): Page-level container for grouping content into regions. Use INSTEAD of Card for settings panels, form groups, and page sections.
- Stack (Layout): Stack layout primitives for horizontal/vertical sequences using flexbox w/ themed spacing tokens.
- Breadcrumbs (Navigation): link trail from root to current page for wayfinding
- Outline (Navigation): Document outline/table-of-contents nav with sliding indicator track. Flat items array {id,label,level}; anchor links; density variant (default/compact); uncontrolled scroll-spy by scroll position (last heading past its resting line = offset + its own scroll-margin-top; first item at top, last at bottom); controlled with activeId; smooth-scroll on click that pins the active item until the next manual scroll. Each link is a Tab stop; Enter/Space activate; no arrow/Home/End movement. onNavigateStart/onNavigateEnd fire around the scroll. Scroll scoping via offset / scrollContainerRef / hasScrollOnClick.
- Pagination (Navigation): Standalone pagination controls for navigating content pages. Supports multiple display variants + works w/ known totals or cursor-based pagination.
- SideNav (Navigation): A sidebar navigation component for organizing application pages with sections, nested items, and icons. Use SideNav as the primary navigation when an app has 5 or more destinations or requires hierarchical grouping.
- Stepper (Navigation): numbered step sequence for multi-step workflows
- TabList (Navigation): Tab strip w/ overflow scrolling; nav landmark by default, WAI-ARIA tabs pattern under role="tablist".
- TopNav (Navigation): Top navigation bar for app headers w/ slot-based layout+companion nav item components.
- useOutlineFromDOM (Navigation): Outline items from h1-h6 inside a DOM element. Updates when those headings change. Empty when the ref is null.
- useOutlineFromMarkdown (Navigation): Headings of a Markdown string as OutlineItem[] for an Outline beside the rendered document. Same parser and heading slugs as Markdown; memoized on source and options.
- BottomSheet (Overlay): mobile touch sheet rising from the bottom edge (native <dialog>): grab handle, opt-in transform-based drag-to-resize snap points (snapPoints: viewport fraction, percent or px length), scrolling area resizes to the snapped visible height on release (a peek stop, a quarter of the sheet or less, keeps the full height and slides instead), Dialog-aligned dismissal purpose (info/form/required), purpose-gated swipe-to-dismiss, fully-expanded Tall visual-viewport mobile-keyboard handling, named height scale, Dialog-like container padding (padding prop, theme bottom-sheet padding, default --spacing-4), modal (default) or non-modal (hasScrim={false}) presentation; modal sheets stack in open order (covered sheet stays mounted, recedes 0.96/−8px then 0.92/−16px, blocked; one scrim; same-update opens ordered by tree; Escape/scrim/swipe pop the top sheet only; a sheet inside a closing sheet leaves with it and returns with it while still open)
- BottomSheetSwitcher (Overlay): deprecated: use one standalone BottomSheet per step with one state value naming the open step (same replace handoff when stepped from inside the open step, no sheetId); keeps working until a future minor removes it. controller for mutually exclusive multi-step BottomSheets, one native dialog per sheet; a scrim flow is one level of the bottom-sheet stack (stacks over or under standalone sheets in open order, recedes as a whole, switching steps keeps its place)
- CommandPalette (Overlay): searchSource-driven command palette dialog; filtering, keyboard nav, grouping, selection; same SearchSource interface as Typeahead
- Dialog (Overlay): modal overlay that blocks page interaction until the user responds
- Drawer (Overlay): side panel floating over content (native <dialog>): start/end edge, full height, Dialog-like container padding (--spacing-4 by default; padding prop or theme drawer padding)
- HoverCard (Overlay): Hover/focus triggered overlay for displaying rich, interactive content anchored to trigger element.
- Lightbox (Overlay): Fullscreen overlay for viewing images and videos at full resolution with gallery navigation and zoom.
- Overlay (Overlay): layered content over media/card surfaces with scrim + hover/focus/controlled reveal
- Popover (Overlay): Click-triggered popover displaying interactive content anchored to trigger element; implements button+dialog ARIA pattern.
- Toast (Overlay): toast notification w/ auto-dismiss, stacking, dedup, smooth animations; MediaTheme inverted surface
- Tooltip (Overlay): Hover/focus triggered tooltip for displaying short, non-interactive text anchored to trigger element.
- List (Table & List): Vertical list for rendering item collections w/ consistent spacing, dividers, marker styles. Composition model: List wraps ListItem sub-components.
- MetadataList (Table & List): label/value metadata display; column layout, collapse, orientation variants
- OverflowList (Table & List): horizontal list w/ overflow indicator: hides items beyond container width
- Table (Table & List): Data-driven table w/ rich cell content via renderCell. Compose cells w/ Badge, StatusDot, Text, Avatar, layout primitives. BaseTable provides unstyled structural core w/ composable plugin pipeline.
- TreeList (Table & List): Data-driven tree list for hierarchical data w/ expand/collapse, branch lines, interactive items. Flat items array w/ recursive children, no composition, no cloneElement.
- Layer (Utility): Layer utilities provide the app-level provider used by overlay systems. Use LayerProvider at the app root for toast/layer configuration; use higher-level Popover, HoverCard, or Tooltip APIs for most overlay UI. Rendered layer content, not the provider’s application subtree, uses theme body text defaults and exits ancestor surface/group membership. Establish intentional groups and complete required providers inside each layer. Every anchored layer keeps a gutter from each viewport edge — the spacing-4 step or the device safe-area inset, whichever is larger — and is capped to the viewport, never to the room beside its trigger: an explicit width renders at its size, flips when it does not fit beside the trigger, and slides into view when it fits on neither side. An app that floats a persistent bar over a viewport edge declares it once as inset on LayerProvider (blockStart, blockEnd, inlineStart, inlineEnd); each edge adds to that edge’s gutter for every anchored layer and moves the toast viewport by the same amount, and defaults to zero. The inset is app configuration, not a theme value.
- VisuallyHidden (Utility): renders content in the a11y tree while hiding it visually (sr-only)
- useTheme (Utility): Programmatic access to theme tokens for SVG/canvas/charts needing JS values instead of CSS vars.
- useThemeName (Utility): The nearest theme name, or null when none is set. Lighter than useTheme.
- useAnnounce (accessibility): Imperative screen-reader announcements via a visually-hidden live region: the page-body one, or one inside the open Astryx modal the caller is rendered in (a native modal hides the body region). Polite + assertive regions created empty on first use + kept mounted, so announcements are reliable (most AT ignore a live region inserted together w/ its content). Messages auto-clear after ~2s.
- useCombobox (focus): Single-select combobox state + keys; focus stays on control. Powers Selector / CommandPalette, and comboboxes over a single-line field you render (search whose results replace a section, an add-people field). Renders nothing: spread getFieldProps / getListboxProps / getOptionProps, or wire role, aria-expanded, aria-controls, aria-activedescendant yourself.
- useFocusTrap (focus): Traps focus within container element following WAI-ARIA dialog focus trap pattern. Listens to document focus events + redirects focus back into container if a Tab from inside moves focus out. Handles both Tab + Shift+Tab wrapping. Tab pressed while focus outside container left to the page. Mouse clicks outside container not intercepted; use light-dismiss handler for that.
- useGridFocus (focus): Manages keyboard navigation within 2D grid following WAI-ARIA grid pattern. Supports arrow keys for cell-to-cell navigation, Home/End for row boundaries, Ctrl+Home/Ctrl+End for grid boundaries, Page Up/Down for custom callbacks (e.g. month navigation in calendars). Boundary navigation callbacks allow cross-grid navigation.
- useIndicatorFocusRing (focus): Draws the standard focus ring on the indicator of a control whose input is visually hidden (checkbox / radio). Painted imperatively on the indicator element (only element whose border-radius shapes the outline), on :focus-visible only.
- useKeyboardHint (focus): Ephemeral "← → to navigate" hint anchored to the focused item on first keyboard focus of a roving-tabindex composite (Toolbar/TabList/SegmentedControl). Teaches sighted keyboard users that arrows move within the group. Kbd-rendered arrows in a top-layer popover="manual", CSS-anchor-positioned (never clipped by overflow), aria-hidden. Stays until first arrow press, Escape, or blur; never re-shows for that instance.
- useListFocus (focus): Manages keyboard navigation within linear list following WAI-ARIA menu/listbox/toolbar patterns. Supports arrow key navigation (vertical / horizontal), Home/End for boundaries, optional wrap-around, Escape to close. Suitable for dropdown menus, toolbars, any 1D focusable list.
- useMultiCombobox (focus): Multi-select combobox state + keys; focus stays on control. Powers MultiSelector. Toggle keeps list open; rows may carry an action cell (grid). Renders nothing, sets no attrs: caller renders + wires ARIA.
- useTreeFocus (focus): Manages roving-tabindex focus + WAI-ARIA tree keyboard model. ArrowUp/Down/Home/End roam linearly over visible treeitems (skip disabled); ArrowRight/Left carry tree semantics (expand/collapse, move to first-child/parent). Enter/Space activate; printable chars trigger typeahead.
- useTypeahead (focus): APG type-to-focus search for a collection. Buffers printable keys (resets after pause), matches labels by prefix ignoring case, accents, stroked letters + Turkish ı/İ in every locale (typed accent prefers exact match), reports index via onMatch. Same letter pressed repeatedly cycles matches. Moves nothing itself; pair w/ useListFocus / useGridFocus.
- createDragToSnapPoints (interaction): A drag that settles an element on snap points (px offsets) at the release, without React.
- createReorderable (interaction): A collection's reorder behavior, for List's reorderable prop; ListItem itemKey on each row.
- useClickableContainer (interaction): Makes container element clickable while preserving nested interactive element behavior. Solves "nested interactive elements" problem: when card is clickable but contains buttons/links, clicking those must NOT trigger card's action. Detects interactive ancestors between click target + container, ignores text selections. Supports href navigation (incl. middle-click + Ctrl/Cmd+click for new tabs).
- useClipboard (interaction): Copy-to-clipboard behavior: clipboard write + transient isCopied flag with reset timer + optional polite SR announcement. One implementation shared by copy affordances instead of re-deriving timer/announce. Rapid re-copies restart the timer; timer cleaned up on unmount. CodeBlock/Timestamp build their copy buttons on it.
- useCollapsible (interaction): Encapsulates collapsible state machine. 3 modes: group-controlled (inside CollapsibleGroup), controlled (isOpen + onOpenChange), uncontrolled (self-managed w/ defaultIsOpen). Used internally by Card + Section.
- useContainerReveal (interaction): Headless hover/focus reveal primitive. Gives a container a scoped trigger that reveals (or conceals) content inside it on hover / keyboard focus: the "row actions appear on hover" pattern. CSS-only: no hover state in React, no re-render on hover. Caller authors no StyleX; hook hands out container + content styles; a nested container shadows its ancestor, so nested containers never leak hover/focus. Accessible: revealed content visually hidden at rest via position + opacity (never display:none), stays mounted + in tab order + announced; reveals on :focus-within, stays visible under a coarse primary pointer, honors prefers-reduced-motion.
- useDragToSnapPoints (interaction): A drag that settles the element at ref on snap points (px offsets): {settleTo}.
- useHotkeys (interaction): Global keyboard shortcuts w/ one window keydown listener per hook instance. Handlers kept in ref; re-renders never re-subscribe. Skips typing targets (input/textarea/select/contenteditable) unless allowInInputs, skips defaultPrevented and IME key events (even with allowInInputs), preventDefault() on match. "mod" = ⌘ on macOS, Ctrl elsewhere. SSR-safe.
- useHoverCard (interaction): Headless hover-triggered floating cards. Builds on useLayer w/ hover/focus intent, delays, safe hover behavior, aria-describedby. Use for rich previews when trigger/content rendering needs full control.
- useInputContainer (interaction): Makes input container wrapper clickable, delegating focus to inner input/textarea when user clicks non-interactive areas (icons, padding, status indicators). Built on useClickableContainer, so nested interactive elements (clear buttons, calendar toggles, links) handled safely; clicking them does NOT steal focus from input. Automatically detects input type: text-like inputs receive .focus(), other types (checkbox, radio, file) receive .click().
- useInputStatusIcon (interaction): On-field status affordance + a11y wiring for bordered inputs. attached = plain glyph (message box carries text); detached = nothing (box has own icon); tooltip = focusable info-tip button reachable by keyboard / pointer / touch / AT.
- useInteractiveRole (interaction): Resolves what a polymorphic component renders as: href -> link, onClick -> button, interactive trigger context -> its role, else inert. Single place the precedence lives.
- useLayer (interaction): Core positioning hook for overlay content via CSS Anchor Positioning + Popover API. Foundation for custom popovers, hover cards, tooltips, fixed-position layers. Both modes use theme body defaults and end ancestor surface/group membership as a whole. Explicit props and unrelated contexts remain unchanged; establish intentional groups and complete required providers inside the rendered layer.
- useLightbox (interaction): State management and accessible trigger wiring for Lightbox. Eliminates boilerplate for open state and index. Returns trigger props and pre-wired Lightbox element.
- useLongPress (interaction): Single-finger press-and-hold detection reporting the touch point. iOS Safari never fires contextmenu on long-press, so this is the only touch route to cursor-positioned surfaces. Cancels on move / lift / multi-touch / unmount.
- useMenuPress (interaction): macOS/iOS menu press model for any pointer: the row under the RELEASE acts, the highlight follows a held pointer, a mouse opens on press and drags in, a finger or a pen opens while down (on press with no delay given, else after its hold). Document-level pointerId tracking; the browser stray click after a touch is swallowed. Already mounted by DropdownMenu / ContextMenu / DropdownMenuSubMenu / Selector / menu bottom sheet.
- useOverlay (interaction): Overlay behavior on a container you already render (Card, media frame) w/o Overlay's wrapper. Spread containerRef + containerProps on it, render element / renderOverlay(children) once inside. CSS-driven via container :hover/:focus-within; hover mode also reveals on keyboard focus. Hidden content is not focusable, so put a focusable element before it, outside the area a revealed scrim covers (the scrim takes pointer input).
- usePopover (interaction): Headless click-triggered popovers w/ focus trap, auto-focus, light dismiss, Escape, optional hidden close button. Every surface emits the canonical popover target. Custom compositions needing a distinct seam pass/document an owned surfaceTarget.
- useToast (interaction): Show toast notifications from anywhere in component tree. Returns function accepting toast options + showing notification. Works automatically w/ LayerProvider / self-mounts fallback viewport.
- useTooltip (interaction): Headless hover/focus tooltip hook. Builds on useLayer w/ hover intent, keyboard focus handling, aria-describedby. Use for custom triggers without wrapper component.
- useAppShellMobile (layout): Reads/controls AppShell mobile nav context. Use for custom triggers, closing drawer after route changes, or syncing AppShell-adjacent mobile UI to the same breakpoint as mobile nav.
- useOverflow (layout): Measures children rendered in hidden container to determine how many fit in available width w/o flickering. Uses ResizeObserver to react to container and measured-child size changes. Measurement container should hold all items plus optional overflow indicator element (identified by data-overflow-indicator attribute).
- useResizable (layout): Adds drag-to-resize behavior to layout regions. Supports single-/multi-region configs w/ snap points, collapsible panels, localStorage persistence, cascade resize ordering.
- useScrollLock (layout): Locks page scroll while active, page stays where it is: overflow: hidden on the root, or on body when its own overflow propagates (wheel, keyboard, scrollbar) + overscroll-behavior-y: none on root and body (no overscroll bounce while locked) + cancels 1-finger pans that would scroll the page (iOS Safari scrolls overflow: hidden pages under a finger); overlay scrollers, range inputs, pinch-zoom + drags on a zoomed page still work. Offset never changes: no jump, iOS toolbar unchanged. Holds the hidden scrollbar's gutter open (scrollbar-gutter: stable) so the page (incl. position: fixed chrome) does not shift sideways.
- useScrollOverflow (layout): Tracks scroll overflow state for horizontally scrollable container. Returns ref callback + state booleans that update as user scrolls / container resizes. Uses scroll event listeners + ResizeObserver for reactive updates. Tolerance of 1px applied to avoid sub-pixel false positives.
- useScrollableArea (layout): Composes logical-axis scrolling into caller-owned viewport/content elements with stable effective-axis and edge state.
- useLinkify (link): Finds URLs, emails and custom patterns in plain text; returns ReactNode[] interleaving plain strings and Link elements that respect LinkProvider routing. Built-in URL/email detection, custom global-regex patterns with href/label builders, overlaps resolved earliest-match-first (custom wins at the same start).
- useImageMode (media): Detects whether image is predominantly dark / light by sampling pixels via OffscreenCanvas. Uses APCA perceptual lightness (sRGB linearization + power curve) for accurate detection, esp. on saturated colors. Runs entirely off paint path: no visible canvas, no layout thrash. Supports regional sampling for detecting luminance where text overlays will appear. Returns null while loading + falls back gracefully on CORS / network errors.
- useMediaQuery (media): SSR-safe media query hook subscribing to window.matchMedia changes. Returns whether given media query matches. Always returns false on first render for SSR compatibility.
- createAnimator (motion & gestures): Animates one element (x, y, scale, rotate, opacity) with Astryx's motion, without React.
- createPanGesture (motion & gestures): Reports a drag on an element as values ({state, translation, velocity}), without React; a finger, a mouse and a pen all drive it, though a mouse or pen drag on selectable text selects it instead (give that text user-select: none). Returns {destroy}.
- useAnimatedLayout (motion & gestures): Handle for a component whose size changes (TreeList, Collapsible): it + content after it inside containerRef glide on one shared motion role. Fixed/stuck sticky stay; never scrolls the area; Reduce Motion respected; every pointer. No handle = snap.
- useAnimator (motion & gestures): Animates the element behind ref (x, y, scale, rotate, opacity) with Astryx's motion; returns the animator.
- useEntryAnimation (motion & gestures): Returns StyleX style for animating element on mount. Only animates when element dynamically inserted after initial page paint; elements rendered on page load not animated. Uses Astryx motion tokens (duration, easing) for consistent timing. Server-rendered elements hydrate without entry style, never animate; elements mounted after hydration animate.
- usePanGesture (motion & gestures): Reports a drag as values ({state, translation, velocity}) for a surface you move yourself; a finger, a mouse and a pen all drive it, though a mouse or pen drag on selectable text selects it instead (give that text user-select: none). Claims at UIKit’s 10 pt; taps, presses and long presses are never a pan, and with axis a scroll across it stays the page’s. Thin layer over createPanGesture(element, options) → {destroy}. No keyboard path of its own: give the drag another way (WCAG 2.5.7). Reduce Motion: honor it in the animation you drive. Prefer BottomSheet snapPoints / Carousel hasSnap when they fit.
- usePressFeedback (motion & gestures): Marks an element as a pressable surface of the touch press model, tracked like a UIKit control (highlight as the finger lands, 150 ms inside a scroller, fade at the lift), and installs the shared document controller; on a coarse primary pointer it also paints mouse, trackpad and Space-key presses at once. Returns the data-astryx-pressable marker to spread; compose one of interactionOverlayStyles on the same element to paint.
- useSnapPaging (motion & gestures): iOS paging for Carousel on native snap's stops: hasSnap={useSnapPaging()}. Finger or trackpad swipe: one view per flick ({pages: 'item'}: one item); mouse wheel keeps native snap. Only that carousel loads the pager.
